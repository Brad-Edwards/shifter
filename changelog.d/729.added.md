Completed the GCP backend bundle contract: the `gcp` entry in the installation registry now ships a closed `GcpBackendSettings` model (`project_id`, `region`, and the composed `range_egress` policy; unknown keys fail closed), an enforced Google Secret Manager reference grammar for `django_secret_key`, the full generated runtime-env projection classified from `installation.runtime_inventory` (secret references vs. public config, with per-role portal/worker/provisioner/range-task consumers), and the canonical GCP validation checks (`terraform fmt`, `helm template`, `kubectl kustomize`, `kube-linter`). Publishing the closed GCP `settings_schema` narrows the GCP operator-facing settings surface (previously accept-any), so the backend-bundle contract is **bumped to version 2** with a migration note; GCP deployments must set `settings.project_id` / `settings.region` and drop any keys outside `project_id`, `region`, and `range_egress`. See `docs/architecture/gcp-backend-bundle-migration-preflight-729.md` and `shifter/installation/published_contract/MIGRATIONS.md`.

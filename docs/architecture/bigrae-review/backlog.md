# Backlog disposition and delivery order

This ledger covers **all 282 baseline open issues**, including their bodies and
available comments, at the commit in [the review](README.md). It is triage, not
a claim that every issue has been implemented or independently live-verified.
The 13 new remediation/research issues below are additional to that baseline;
#2080 is the review itself. No existing issue or PR was closed by this review.

## Delivery program

Three milestones constrain the first GCP/GCE adoption path. They have acceptance
outcomes rather than invented dates. Only focused prerequisite issues were moved;
the AWS, communications, vendor and historical feature programs retain their
separate scope. The old closed CTF GA milestone held 71 open items at baseline;
its closure is not evidence that those requirements are satisfied.

- [BigRAE GCP 1 — scope and security foundations](https://github.com/Brad-Edwards/shifter/milestone/35): authority, contract and effective security foundations.
- [BigRAE GCP 2 — reliable operations](https://github.com/Brad-Edwards/shifter/milestone/36): observable lifecycle, containment, fresh install and recoverability.
- [BigRAE GCP 3 — qualified scenarios and adoption](https://github.com/Brad-Edwards/shifter/milestone/37): released scenarios, maintainable supported core, handbook and evidence-based release decision.

The critical path is ownership/scope → effective security and version contracts
→ lifecycle/monitoring/recovery → qualified cohort → adoption decision. Work with
no dependency can start independently, including the browser CSP change.
GitHub blocking relationships encode this order, using the REST API's numeric
issue IDs, following the
[issue-dependencies API](https://docs.github.com/en/rest/issues/issue-dependencies).
They do not themselves prevent merging code or closing an issue:
#2092 must check completion **and evidence** before declaring readiness.

## Scope decisions that avoid unnecessary work

- Keep #1937, #681, #1586, #1295, #1019/#1020, #615, #202, #1531 and #1526 as
  canonical owners. #2083 supplies the missing implementation after #1586's design.
- Keep #1949 as the broader kit program; #2082/#2091 select and qualify the first
  cohort. Additional mechanisms in #1967–#1969 and #2050/#2054 become prerequisites
  only when the selected scenario needs them.
- Use #1525/#2049 for durable critical delivery if the release claims email-based
  account/invitation workflows. The scope decision must explicitly qualify or
  exclude those workflows; it cannot waive security on an exposed retained path.
- Preserve #2069, #1894, #1829/#1958 and #1830 as AWS qualification/retirement work.
  The GCP slice of #2041 is tested under #2091 without waiting for AWS completion.
- Keep #28/#2076 and #2093 optional. Neither warm pools nor additional runtimes
  are needed to demonstrate the initial GCE scenario envelope.
- Partially supersede #1866's second documentation-platform proposal; keep ADR-038
  and consolidate optional Scorecard work with #1743 after checking evidence.
- Keep historical #1539 and #2062 reporting obligations honest. A merged PR is
  not a reason to erase unfinished live validation or required reporting.

The applicable Ground Control project remains `shifter`. Existing requirement
UIDs are preserved. New review planning issues do not invent requirements or
claim implementation traceability. Reconcile requirement changes and statuses
through the supported Ground Control tools when implementation starts; requirement
entity tools were not exposed during this review session.
